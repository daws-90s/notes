Upgrading EKS cluster using terraform and blue-green
====================================================
zero downtime, but we announce downtime

atleast 3 months before, announce the date and time to applications. change SG rules so that no app team can access cluster in that team

1. EKS Control plane and EKS nodes

-> upgrade EKS control plane. 1.35 -> 1.36
-> green node group. 1.35

ALB -> Listener -> Rule -> TG -> Pod
apps will not go down, we cant interact with cluster for any changes

-> create another node group blue with 1.36 version

EKS control plane = 1.36
EKS blue NG = 1.36
EKS green NG = 1.35

-> cordon gree nodes -> scheduling disabled
-> drain green nodes
-> remove green ng

terraform apply -var="eks_version=1.36"

for addon in vpc-cni eks-pod-identity-agent coredns kube-proxy metrics-server; do
  LATEST=$(aws eks describe-addon-versions \
    --kubernetes-version 1.36 \
    --addon-name $addon \
    --query 'addons[0].addonVersions[0].addonVersion' \
    --output text)

  aws eks update-addon \
    --cluster-name roboshop-dev \
    --addon-name $addon \
    --addon-version $LATEST \
    --resolve-conflicts OVERWRITE \
    --region us-east-1
done

terraform apply \
  -var="eks_version=1.36" \
  -var="blue_version=1.36"
  
eks_version -> 1.36
blue_version -> 1.36

upgrade EKS control plane to 1.37, blue 1.36
update addons
create green ng 1.37
cordon blue nodes
drain blue nodes
