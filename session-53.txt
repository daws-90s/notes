Volumes
========
Containers/Pods are ephemeral. data stored inside pod will be deleted once pod is deleted.
EKS cluster is ephemeral including nodes

EBS vs EFS vs S3
=================
S3 is object storage, we can mount S3 to the instances. S3 storage is only accessible through HTTP/HTTPS

EBS vs EFS
===========
1. EBS is like HD, EFS is like MS Drive
2. EBS can only be attached to one instance at a time, EFS can be attached to multiple instances
3. EBS is block store, EFS is file system
	data is stored as blocks in drives. each block is 4kb size, filesystems are responsible to bring the data from disks. filesystems performs CRUD operations on the blocks.
	
	format disk, create file system and mount to instance.
4. EFS file system is already decided by AWS as NFS protocol. here we have only step mount to the instance.
5. EBS is faster than EFS.
6. OS, Database servers EBS is the best option, EFS can't work for this. normal files can be stored in EFS.
7. EBS is fixed size, EFS is not fixed it grows automatically
8. EBS should be in the same az as instance. EFS can be anywhere in the network
9. EBS does not need SG, EFS requires SG

hostPath
=======
if you store pod data in the host, pod is deleted and recreated, it can be scheduled in any other node pod can't mount data in other node.

hostpath is used to ship the host logs outside of kubernetes like ELK. we mount hostPath to containers and allow containers to ship the logs.

hostPath is not secure, we use in rare cases like shipping host logs to ELK, here we can take a precaution of readOnly true..

daemonset -> kubernetes make sure of running one pod replica in each and every node. this pod is used to collect host metrics, logs, etc using hostPath

access modes
============
1. readWriteOnce -> at a time only one node can access. pods in that node can access
2. ReadOnlyMany -> at a time multiple nodes can readOnly
3. ReadWriteMany  -> at a time multiple can read and write
4. ReadWriteOncePod  -> only one pod can read and write

reclaim policy
============
1. delete -> Automatically removes both the PV object from Kubernetes and the actual storage
2. Retain -> data will be persisted even pv and pod is deleted
3. Recycle -> data will be erased but disk will be there.
